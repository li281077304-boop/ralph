USER OBSERVATION
The Dashboard Widget run finished end to end (`dashboard-widget-real-20260916-r2`, DONE/done/round 5, HEAD `a115f1b`), but its own telemetry shows the system-level defects: a supervisor restart counter of 231 with every entry parked at `WAITING_FOR_CHIEF`/waiting, and a real Chief failover that had to be performed by an operator because the permanent router could not do it. The instruction is to repair Ralph Core using that finished run as accident evidence, and not to continue, replay, or re-implement the Dashboard Widget.

CONFIRMED FACT
Machine Gate consulted `policy_passed` while ignoring the required commands it had just executed, so `commands: [{command: "exit 1", exitCode: 1}]` could still reach CHECKPOINT and commit. The supervisor re-evaluated only "is the process gone" and had no legal-wait concept, so a run parked in a legal wait was restarted forever. There is a Chief Router (`ralph-chief-v3-router.js`) but no execution-backend abstraction at all, so switching from Host Codex to an external Agent required hand-editing durable state. Round artifacts for rounds 1–4 of the finished run hash identically before and after the failover, so durable history is stable and usable as regression evidence.

TECHNICAL ASSESSMENT
The three gaps share one root shape: an authority that was inferred from a convenience signal instead of being derived from durable evidence. The gate inferred "passed" from `policy_passed`; the supervisor inferred "unexpected exit" from process liveness; the failover was a manual state edit because no adapter boundary existed. Each repair therefore introduces one explicit authority module — `gate-evidence.ts` for required-command judgement, `supervisor-policy.ts` for restart disposition, `execution-backend.ts` for backend routing — and makes the existing call sites consult it rather than re-derive it.

REJECTED ASSUMPTIONS
A passing policy check is not a passing gate. A parked run is not a dead run. An unusable backend is not a failed run. The Dashboard run must not be resumed or replayed to demonstrate the fixes, and the Dashboard Widget must not be rebuilt. The 231 restarts must not be described as a human business problem.

DECISION
Fix the three gaps in Ralph Core only, enforce each one at two independent layers where the boundary is destructive (gate + checkpoint, gate + review binding), and prove each with real, safe UAT: a real Git repository with a real bare remote and a deliberately failing required command for P0; real supervisor child processes with real SIGKILL and real durable state for P1; the anonymized durable fixture of the finished Dashboard run plus deterministic router tests for P2.

UNKNOWN / OPEN RISKS
No long unattended production run has yet exercised the new restart matrix live. The permanent execution-backend router has not itself initiated a live production failover — the finished run proves the failover is real, history-preserving behaviour, not that this router performed it. WorkBuddy is deliberately not a supported backend yet. Rounds 1–4 of the Dashboard run predate the required-command contract, so their gate artifacts would have to be regenerated by re-execution rather than trusted.
